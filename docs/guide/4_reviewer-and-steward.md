# Reviewer and steward

You approve changes to the element types you are responsible for, and you keep
their content true.

## What you check

- **Why.** The proposal says what the change serves, or that it is purely
  technical. The branch shows how each row was settled in the conversation.
- **Trace.** Every new or changing element below the business layer traces up
  to the business or strategy it serves.
- **Boundary.** Nothing on the branch is the inside of one system. A part linked
  from its system is not a gap: that is where its detail belongs.
- **Impact.** What the branch leaves pointing at an element it retires is
  retired too, moved, or left on purpose.
- **States and work packages.** Every changing element says what changes and
  which work package delivers it.

## How you work

Open the branch and read its changes, its proposals and what it touches.
Approve the types you review, or send the branch back with a comment. A branch
merges when every type it touches is approved.

## As a steward

You own content, not only changes: owners, descriptions, attributes. Correct
them on a branch like any other change. What a source system feeds is corrected
at the source, so the next feed does not undo the correction.
